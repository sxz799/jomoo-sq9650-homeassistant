# 九牧 SQ9650 智能马桶 Home Assistant 集成

通过蓝牙 BLE 把九牧 SQ9650 轻智能马桶接入 Home Assistant。集成以自定义组件形式运行，直接复用 HA 的蓝牙栈（本机适配器或 ESPHome 蓝牙代理），把马桶的私有协议封装成按钮、开关、选择器、传感器等实体。

仓库同时保留了九牧微信小程序的反编译源码（`OUTPUT/`），仅作为协议参考，不参与运行。

## 二、功能概览

- **动作控制**：小冲 / 大冲 / 翻盖 / 翻圈 / 魔力泡 / 待机
- **座温调节**：常温 / 中温 / 高温 三档
- **功能开关**：自动冲刷、关盖冲厕、脚感控制、夜灯、智能夜灯、预润湿、落座发泡
- **状态回读**：工作状态、着座、盖板、座圈、冲水、故障、蓝牙连接状态
- **连接可控**：手动“连接”/“断开”按钮，空闲 60 秒自动断开，把马桶蓝牙让给手机小程序
- **自动发现**：广播中出现 FFE0 服务或 `JOMOO_SMART_*` 名称时，HA 会主动提示添加

***

## 三、前置条件

1. **Home Assistant**（支持自定义集成，建议 2024.x 及以上）。
2. **可用的蓝牙连接通道**，满足以下任一条件：
   - HA 主机自带蓝牙适配器，且能正常连接 BLE 外设；
   - 使用 ESPHome 蓝牙代理（ESP32），并在 HA 中启用 `bluetooth` 集成。
3. 马桶处于配网/可连接状态，且与蓝牙适配器/代理距离足够近（建议同一房间）。

> 经验提示：HA如果安装在虚拟机中使用硬件直通的蓝牙可能无法使用。这种情况请改用 ESP32（ESPHome `bluetooth_proxy`）作为蓝牙代理。

## 四、安装

1. 把 `ha_custom_component/jomoo_ble` 整个目录复制到 HA 配置目录下的 `custom_components/jomoo_ble`：
   ```
   <HA 配置目录>/custom_components/jomoo_ble/
   ```
   也可以直接解压 `jomoo_ble.zip` 到该位置（压缩包内已是 `jomoo_ble/` 目录结构）。
2. 重启 Home Assistant（或“开发者工具 → 重新加载自定义集成”）。
3. 添加集成：
   - **自动发现**：马桶广播出现后，HA 通知里会出现 “JOMOO Smart Toilet (BLE)”，点击确认即可；
   - **手动添加**：设置 → 设备与服务 → 添加集成 → 搜索 `JOMOO`，输入马桶蓝牙 MAC（可用 nRF Connect 扫描得到，格式 `AA:BB:CC:DD:EE:FF`）。
4. 添加完成后，设备页会出现“控制”“传感器”等区块。默认**不会自动连接**，需要点 `bt01-连接` 才会占用蓝牙。

## 五、实体清单

### 按钮（11 个）

| 实体          | 说明                  | 下发命令       |
| ----------- | ------------------- | ---------- |
| `bt01-连接`   | 主动连接马桶，空闲 60 秒后自动断开 | —          |
| `bt02-断开连接` | 立即断开，释放蓝牙给手机小程序     | —          |
| `bt03-小冲`   | 小水量冲水               | `0x35` / 1 |
| `bt04-大冲`   | 大水量冲水               | `0x35` / 2 |
| `bt05-翻盖开`  | 打开盖板                | `0x33` / 1 |
| `bt06-翻盖关`  | 关闭盖板                | `0x33` / 0 |
| `bt07-翻圈开`  | 打开座圈                | `0x34` / 1 |
| `bt08-翻圈关`  | 关闭座圈                | `0x34` / 0 |
| `bt09-魔力泡`  | 启动魔力泡（发泡）           | `0x46` / 1 |
| `bt10-待机`   | 进入待机/休眠             | `0x17` / 1 |
| `bt11-刷新状态` | 查询并刷新状态上报           | `0x11` / 0 |

### 开关（7 个）

| 实体          | 说明      | 下发命令            | 状态回读      |
| ----------- | ------- | --------------- | --------- |
| `sw01-自动冲刷` | 离座自动冲水  | `0x40` / `0x05` | 支持        |
| `sw02-关盖冲厕` | 关盖后自动冲水 | `0x40` / `0x14` | 支持        |
| `sw03-脚感控制` | 脚感翻盖/冲水 | `0x40` / `0x0E` | 支持        |
| `sw04-夜灯`   | 夜灯开关    | `0x41` / `0x00` | 支持        |
| `sw05-智能夜灯` | 光感自动夜灯  | `0x40` / `0x02` | 支持        |
| `sw06-预润湿`  | 落座前预润湿  | `0x40` / `0x12` | 支持        |
| `sw07-落座发泡` | 落座自动发泡  | `0x40` / `0x0C` | 不上报（乐观状态） |

> `sw07-落座发泡` 的开关状态不会被马桶上报，界面显示的是最近一次操作结果；`sw05-智能夜灯` 与 `sw04-夜灯` 是两个独立开关。

### 选择器

| 实体   | 选项           | 下发命令           |
| ---- | ------------ | -------------- |
| `座温` | 常温 / 中温 / 高温 | `0x3C` / 0、3、5 |

> 硬件只响应 `0`（常温）、`3`（中温）、`5`（高温）三档，其余档位会被忽略。

### 传感器

| 实体     | 类型       | 说明                                 |
| ------ | -------- | ---------------------------------- |
| `工作状态` | 文本（ENUM） | 待机 / 休眠中 / 自清洁中 / 预湿润中 / 自检中 / 工作中 |
| `蓝牙连接` | 二值（连接）   | HA 与马桶之间的 BLE 链路是否在线               |
| `着座`   | 二值（占用）   | 是否有人落座                             |
| `盖板`   | 二值（开合）   | 盖板是否打开                             |
| `座圈`   | 二值（开合）   | 座圈是否打开                             |
| `冲水`   | 二值       | 是否正在冲水                             |
| `故障`   | 二值（故障）   | 故障字节任一位置位；做了两帧去抖                   |

## 六、连接策略

马桶的 BLE 通道同一时间只能被一个中心设备占用，因此集成采用“按需连接 + 空闲释放”的策略：

- 集成加载后**不自动连接**，实体仍可正常显示（状态为未知/不可用直到首次拿到上报）。
- 点击任意控制实体（按钮/开关/选择器）或 `bt01-连接` 时自动建立连接。
- 每次下发指令、查询状态都会重置空闲计时；**连续 60 秒无操作自动断开**（`const.py` 中的 `IDLE_DISCONNECT_SECONDS`）。
- 手动点 `bt02-断开连接` 或卸载集成时立即断开。
- 断开后手机小程序可正常使用；再次操作 HA 时会重新连接（连接成功后先发一帧状态查询，与小程序 `onDeviceReady` 行为一致）。

状态更新完全由马桶的 `0x30` 上报驱动，集成**不做轮询**；需要主动刷新时点 `bt11-刷新状态`（等待上报超时 2 秒）。

## 七、BLE 协议说明

协议来源为九牧微信小程序反编译源码 `OUTPUT/utils/bluetooth/toilet/TechramicToiletController.js`（SQ9650 的 `bleProtocol = 1`，对应 Techramic 协议）。

### 7.1 GATT 服务

| 用途   | Service UUID                           | Characteristic UUID                    | 属性                              |
| ---- | -------------------------------------- | -------------------------------------- | ------------------------------- |
| 主控通道 | `0000ffe0-0000-1000-8000-00805f9b34fb` | `0000ffe1-0000-1000-8000-00805f9b34fb` | Write Without Response + Notify |

### 7.2 下行帧格式

```
FC <SUM> 01 00 00 00 <CMD> [<SUB>] [<VAL>] FC
```

- 第 0 字节固定 `FC`（帧头），最后一字节固定 `FC`（帧尾）
- 第 2\~5 字节固定 `01 00 00 00`（手机侧地址标识）
- `SUM = sum(frame[2 .. len-2]) & 0xFF`（**累加和**，不是异或）
- 单参数命令 9 字节，双参数命令（`0x40`/`0x41` 系列）10 字节

### 7.3 上行状态帧

```
FC <SUM> 00 FF 00 00 30 <18 字节状态数据> FC      # 共 26 字节
```

集成仅处理 `frame[6] == 0x30` 且长度 ≥ 26 的帧，`t = frame[7:]` 的字段映射如下：

| 字段                                     | 位置                                               |
| -------------------------------------- | ------------------------------------------------ |
| 工作状态                                   | `t[0] & 0x1F`                                    |
| 故障                                     | `t[1] \| t[2] \| t[3]` 任一非 0                     |
| 脚感 / 盖板 / 座圈 / 着座                      | `t[4]` 的 bit3 / bit4 / bit5 / bit7               |
| 冲水档位 / 四季温感                            | `t[5]` 的 bit0-1 / bit2                           |
| 座圈动作 / 盖板动作 / 预润湿 / 自动小冲 / 关盖冲厕 / 定期冲刷 | `t[6]` 的 bit0 / bit1 / bit2 / bit3 / bit4 / bit7 |
| 自动翻盖                                   | `t[8]` bit7                                      |
| 夜灯 / 智能夜灯                              | `t[9]` 的 bit6 / bit7                             |
| 自动冲刷 / 座温档位 / 智能节电                     | `t[10]` 的 bit7 / bit3-5 / bit6                   |

### 7.4 命令表

| 语义              | 帧内容（CMD / SUB / VAL）                      |
| --------------- | ----------------------------------------- |
| 大冲 / 小冲         | `0x35` / `02`、`0x35` / `01`               |
| 魔力泡             | `0x46` / `01`                             |
| 待机              | `0x17` / `01`                             |
| 查询状态            | `0x11` / `00`                             |
| 翻盖开 / 关         | `0x33` / `01`、`0x33` / `00`               |
| 翻圈开 / 关         | `0x34` / `01`、`0x34` / `00`               |
| 座温 常温 / 中温 / 高温 | `0x3C` / `00`、`0x3C` / `03`、`0x3C` / `05` |
| 脚感开 / 关         | `0x40` / `0E` / `01`、`00`                 |
| 自动冲刷开 / 关       | `0x40` / `05` / `01`、`00`                 |
| 智能夜灯开 / 关       | `0x40` / `02` / `01`、`00`                 |
| 预润湿开 / 关        | `0x40` / `12` / `01`、`00`                 |
| 关盖冲厕开 / 关       | `0x40` / `14` / `01`、`00`                 |
| 落座发泡开 / 关       | `0x40` / `0C` / `01`、`00`                 |
| 夜灯开 / 关         | `0x41` / `00` / `01`、`00`                 |

### 7.5 故障去抖

实测 `t[1]`（帧第 9 字节）中“亮度传感器故障”位会在 `0x40` / `0x00` 之间逐帧翻转，属于设备端误报抖动。集成要求**连续两帧故障字节完全一致**才对外公布 `故障` 实体状态，避免实体在“正常/异常”之间来回跳变。

## 八、常见问题

**1. 添加时提示“蓝牙范围内未找到设备”**

- 确认马桶通电且在附近，广播可达；
- 确认 HA 的 `bluetooth` 集成正常、代理在线；
- 用 nRF Connect 确认 MAC 地址与设备名（`JOMOO_SMART_*`）；
- 若主机自带适配器扫描到却连不上，改用 ESPHome 蓝牙代理。

**2. 操作时提示连接失败**

先在集成页面启用调试日志：设置 → 设备与服务 → JOMOO Smart Toilet (BLE) → ⋮ → 启用调试日志，然后在“日志”页勾选 `debug` 级别。日志会打印广播来源（`hci*` 本机适配器 / 代理）、RSSI、连接失败异常类型，以及每一帧上报的原始十六进制与校验结果。

**3. 手机小程序无法使用**

HA 与小程序不能同时占用同一条 BLE 链路。点 `bt02-断开连接`（或等 60 秒空闲）后即可在小程序操作；HA 再次操作会自动重连。

**4. 实体名称/顺序不对**

- 实体名（如 `bt01-连接`、`sw01-…`）中的编号前缀只影响设备页“控制”区块的排序，该区块由前端按名称/拼音排序，集成无法直接指定顺序。
- HA 的实体名称与注册顺序**只在首次注册时确定**，改完代码后需要删除旧实体并重启，或直接在仪表盘用 `entities` 卡片自定义排列。

**5. 集成图标不显示**

修改 `brand/` 后需要重启 HA 并强制刷新浏览器（`Ctrl + F5`），部分版本还需清理浏览器图标缓存。

**6. 自动冲刷开关状态与小程序不一致**

如发现 `sw01-自动冲刷` 回读位与本机实际设置不符，请附上调试日志中的 `0x30` 原始帧，便于重新定位字段位置。
